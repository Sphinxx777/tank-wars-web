# Terrain collapse and tank placement

This follow-up checks the original Tank Wars 3.2 executable, SHA-256
`659ace6b9a97c30191a8f65cf25f22322c087166909e9fa1d522e529adbafd9d`.
Offsets below are file offsets in the local original EXE or OVR. The binary itself is
not distributed with this repository.

## Collapsing earth is visibly incremental

EXE **0x5e46–0x5f1a**, resident `431:496`, operates directly on VGA memory. It has
**no Delay, Sound, random-number, or frame-sync calls**. Consequently its wall-clock
speed depends on the original machine. A browser needs an explicit pacing policy;
that policy must not be described as a recovered DOS time constant.

The initial scan uses `STD; REPNE SCASB` beginning at offset 64000, with AL=2.
This means descending framebuffer offsets: bottom to top, **right to left** within
each row. The original boundary prevents dirt from falling outside the playfield.
Only palette 2 is moving earth. A destination accepts earth exactly when its color
is 0 or 30 through 99 inclusive. Tanks (20–29), boundary 13, and other foreground
colors block it.

For each accepted move, the original:

1. Writes dirt to the pixel one row below.
2. Restores the vacated position from the original sky/background buffer.
3. Appends the destination address to an active list, maintaining scan order.

After this initial single-row scan, each active-list sweep moves surviving entries
one further row. An entry whose destination is blocked is permanently removed by
zeroing it. The remaining entries are visited in their original order. Processing
ends when no active entries remain. See **0x5e64–0x5ea7** (initial scan),
**0x5ea9** (sentinel), **0x5eb4–0x5f14** (subsequent sweeps).

`tools/verify-crumble-oracle.py` executes these exact original instructions using
Unicorn. `tests/fixtures/crumble-oracle.json` records four small input scenes,
initial active-list order, and every distinct full sweep. Inputs cover stacked
earth, an uneven island, tank-colored obstacles, and palette boundary cases.
The expected frames are generated by the original machine code, not by a second
implementation of the JavaScript algorithm.

The probabilistic gate at OVR **0x1ad57–0x1ada1** rolls once for the whole event;
it does not randomly select individual pixels. Its original comparison permits
collapse on `random()*100 <= crumbleSetting`. Sonic invokes the full collapse
routine directly. Dirt Slinger has a separate doubled-chance invocation.

## No launch pads

Terrain generation ends before player placement. The initial tank-placement loop
at OVR **0x1d09b–0x1d311** does not fill or level any earth under tanks. The earlier
web code's seven-column launch pads had no basis in this routine.

Initial placement sets each tank's bottom coordinate to **y=32** at **0x1d1ad**.
It checks palette membership at `(x+dx,y+1)` for all dx from -4 through +4.
The set stored at OVR **0x1ca24** contains precisely colors **2 and 13** (earth and
boundary). If **any** of those nine positions supports the tank, the initial fall
stops. Otherwise it restores the old body, increments y by one, and draws the new
body. The loop is **0x1d1d4–0x1d2ee**. There is no initial fall damage or sideways
slide. The delay at **0x1d28c** is DS:e8c8, 5 ms in the supplied configuration.
The original can skip that delay when its startup/keyboard skip flag is set.

Initial gun elevations are also positional, not based on the midpoint x=160.
The Pascal set at OVR **0x1ca04** is `{1}`; **0x1d11e–0x1d127** unions in the last
player index. First and last receive 75 degrees; all interior players receive
90 degrees (**0x1d136/0x1d146**). Only the last faces left (**0x1d15a–0x1d17b**).
In a single global-angle representation these are 75, interior 90, and last 105.

## Subsequent tank falling is a different loop

OVR **0x1a9b6–0x1acd9** checks tanks in ascending player index. The supporting
palette set at **0x1a996** is again `{2,13}`. Tank palette colors are not members.
The initial eligibility condition is:

- Tank is alive.
- None of the seven inner positions x-3 through x+3 at y+1 is support.
- Both outer positions x-4 and x+4 are not simultaneously support.

Evidence: **0x1a9e8–0x1aa94**. Once eligible, the loop does the following:

1. Save the old x,y and draw the body there.
2. Increment y (**0x1abb9**).
3. If `(x+4,y+1)` is support, decrement x (**0x1abed–0x1abf5**).
4. Independently check `(x-4,y+1)` using that possibly updated x; if supported,
   increment x (**0x1ac29–0x1ac31**).
5. Continue falling unless **all nine** positions x-4 through x+4 at y+1 are
   support (**0x1ac35–0x1ac7b**). This differs deliberately from the initial
   landing test, which stops on any support.
6. Apply `Random(3)+1` damage through defense type 1 (fall shield), then wait
   DS:e8c8 milliseconds (**0x1ac7d–0x1aca2**).
7. Restore the old body from the original background (**0x1aca7–0x1acb5**).

Damage occurs for each fallen pixel, including the landing pixel, rather than as
one accumulated damage event at the end. The loop does not recheck men or alive
between pixels. The later death pass handles lethal fall damage. It awards no
per-man hit points during the fall; existing current-shooter kill accounting
happens afterward.

Before the loop, the gun line is restored from background (**0x1aac7–0x1ab65**).
Afterward `431:7ba` redraws the body and gun at its final coordinates
(**0x1acc3–0x1acc6**).

## Restoring a tank does not preserve the earth behind it

Resident `431:685`, EXE **0x6035–0x6167**, copies the original background pixel
for each of the body's exact 33 pixels into VGA memory, unconditionally. It is
not a temporary sprite overlay backed by a snapshot of destructible earth.
Therefore drawing/restoring a body can erase earth that overlaps its shape.
A layered browser renderer must explicitly reproduce those terrain writes;
otherwise a tank can keep colliding with earth already erased by the original.

The exact body includes nine bottom-row pixels, seven each two and three rows
above it, seven separated pixels one row above it, and three at the top; use the
existing extracted body bitmap rather than a filled rectangle. Barrel restoration
similarly follows its rasterized line rather than clearing a bounding box.

## Death settlement order

After each death effect and score update, OVR **0x15a3f–0x15a50** redraws the
boundary, invokes the probabilistic crumble wrapper, and invokes tank falling if
enabled. It then continues the ascending-index death scan. The outer scan repeats
when a death or anti-stalemate lightning set DS:480f, checked at
**0x15aa9–0x15ab0**. That flag is set explicitly for a death at **0x158a1**, not
merely because a terrain pixel moved.

The findings above establish control flow and pixel rules. They do not establish
an exact wall-clock rate for the assembly-only crumble routine or eliminate all
remaining differences caused by the web renderer's layered framebuffer model.
