# Original gameplay and menu backgrounds

Decoded from BOMB.OVR / BOMB.EXE, 2026-10-18. Implemented by `dist/background.js`.
All offsets are hexadecimal file offsets. These are indexed bitmaps generated once,
with an independently rotating palette. No bitmap coordinates change during palette
animation, and rendering consumes no RNG.

## Gameplay recipe

The dispatch routine is OVR **0x1c0c0..0x1c937**. Indices30..59 normally contain
30 colors generated by resident **EXE0x59bc..0x5b87**: three random RGB6 anchors,
nine R(64) calls; ten linearly interpolated samples per segment, truncated.
Palette0 is explicitly changed to RGB6(14,9,10) at **OVR0x1cb3d..0x1cb4c**, or
RGB8(57,36,40). None therefore is this dark brown, not pure black. Palette2 remains
standard green; this procedure does not randomly change dirt color.

| 2 Bars | y31..190, horizontal x11..310, index30+(y mod30) | Random30-color ramp |
| 3 Circles | r0..170, outline ellipses centered(160,110) then(161,110), both radii r, index30+r mod30; clip11..309,31..189 | Random30-color ramp |
| 4 Spread | Rays from(160,100) around top left→right, right top→bottom, bottom right→left, left bottom→top, including corner twice; nth ray index30+2(n mod15) | Random30-color ramp |
| 5 Sky | y31..190, horizontal x11..310, index30+trunc((y-30)/8) | RGB6(i,0,63-i),i0..19; **no animation, no palette RNG** |
| 6 Static | x11..309 outer loop,y31..189 inner loop, each pixel index30+R(30) | Random30-color ramp followed by47541 pixel calls |
| 7 Rectangle | Last ring [80,150,159][R(3)]; i1..last inclusive: outline rectangle(10+i,30+i,310-i,190-i),index30+i mod30 | Random30-color ramp, then one R(3) |

Stars OVR1c0e9..1c220; Bars1c223..1c297; Circles1c29a..1c366;
Spread1c369..1c569; Sky1c56c..1c5e9; Static1c5ec..1c6a6;

**Correction to earlier research:** the two Circles helpers are not random.
Resident `dbd:3d`/`dbd:66` (EXE0xf2ad/0xf2d6) calculate the midpoint of the BGI
viewport, subtracting the viewport origin. The ellipse helper adds that origin
again (EXE0xe677..0xe680), producing fixed centers160,110 and161,110.

Asterisk first loops i0..149, with center160,110 and endpoints(160-i,31),
(160+i,31),(160-i,189),(160+i,189), color30+i mod30, in that order. Then i0..79,
endpoints(11,110-i),(309,110-i),(11,110+i),(309,110+i), color30+(i+70)mod30.

Rectangle helper `cc8:31` does not reject crossed coordinates. Later rings in
modes150/159 overwrite earlier rings. Do not approximate using distance to edge.

After every generated backdrop, including None/Sky, **one additional Random(real)** at
OVR1c9a6..1c9b9 toggles the persistent palette direction with probability0.5.
Helper EXE0xe258 swaps interrupt handlers:0xdf13 increments offset,0xdfc5
decrements it (wrapping negative offset to last palette entry). Preserve
`model.direction` between rounds; the optional generation parameter defaults+1.

RND selection is a single R(9) at OVR1cafc..1cb0d. USER repeatedly samples R(9)
until the selected bit of its allowed mask is set (1cb11..1cb3a).

## Raster verification

The game's private line helper is `cc8:9e4`, EXE0xed04..0xeddd, not the BGI font
line routine. It normalizes endpoints left-to-right and advances a half-major
error accumulator. A Unicorn execution of the original code generated every line
of complete backgrounds2,4,5,7(mode80),8. All five maps matched the new JS:
**0 differing pixels out of64000 for each map.** Golden hashes are in
`tests/background.test.mjs`.

Circles use the exact ellipse translation exported from `effects-render.js`;
its machine-code verification is documented in `explosion-visuals.md`. Full
Circles screen capture comparison is still pending. RGB random ramp arithmetic
is decoded; rare Turbo Pascal Real rounding edges have not been exhaustively
compared for all possible anchor combinations.

## Menu and score

OVR0x417e..0x431a. Palette index i30..59 is RGB6(i,0,i).
Mode0 draws outlines(i,i,319-i,199-i), index30+i mod30, for i0..last inclusive;
last is100 or160, selected by one R(2). Mode1(score/shop) is fixed horizontal
rows index30+y mod30.

`research/screenshots/dos-menu.png` is the100-ring variant with palette phase0.
All **42942 visible magenta background pixels** match `createMenuBackground(0,100)`
exactly in RGB. The160-ring variant matches39949 and is not this captured variant.
The clipped portions inside recessed buttons must redraw the same cached model.

## Palette timing and integration API

Hardware cycle handler EXE0xdf13..0xdfc3 advances an8-bit counter per interrupt,
updates palette when counter>=delay, resets counter, uploads the30(or20) colors
starting at offset, then increments offset. First update uses offset0. Delay0/1
both update every interrupt. Stars use delay **3*(configured speed+1)**
(OVR1c213..1c21d), all other animated modes use configured speed.

The reference program can install BIOS INT1Ch (~18.2065Hz) or VGA retrace IRQ.
The module defaults to BIOS1193182/65536Hz; it accepts an explicit tickHz if the
reference configuration is measured differently. Exact phase across screen changes
and browser suspension needs integration to preserve the chosen start time.

- `createBattleBackground(kind,rng,{mask=511,direction=1})` returns
  `{kind,pixels:Uint8Array(64000),palette:RGB8[][],base:RGB8[],cycle:boolean,direction:+1|-1}`.
  `rng` supplies `int(n)` and `next()` (the latter has an integer fallback); generate once per round and retain this object. Stars
  additionally expose their ordered list; Rectangle exposes lastRing.
- `createMenuBackground(mode=0,lastRing=100)` generates a pure model without RNG;
  caller may select lastRing with its menu RNG once. Mode1 is score/shop.
- `backgroundFrame(model,elapsedSeconds,speed,outRGBA,tickHz)` fills/reuses RGBA.
- `backgroundPhase(model,elapsedSeconds,speed,tickHz)` gives rotated offset.

Save the generated bitmap/palette or enough deterministic generation state; do
not regenerate from the live gameplay RNG during repaint or save restore. Older
saves' geometry was approximate and lacks the random static bitmap; a separate
seeded reconstruction avoids changing their future gameplay RNG state.
